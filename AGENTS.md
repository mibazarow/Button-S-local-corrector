# AGENTS.md — правила работы над BUTTON-S

Этот файл — **не описание проекта**, а инструкция агенту: как работать с этим
репозиторием, что можно менять, как проверять и в каком порядке действовать.
Фактическое состояние проекта — в `.internal/context.md`, требования — в
`.internal/TZ.md`. Это локальные документы, они не публикуются в репозитории.

---

## 1. Что за проект (минимум для ориентира)

- **BUTTON-S** — фоновый ускоритель ввода для macOS: меню-бар, без иконки в Dock.
- Автоподмена раскладки, опечатки, автозамены, капитализация, списки, залипший
  Shift, голосовой ввод (Whisper локально), LLM-промпты и перевод, история,
  словари, исключения приложений.
- Стек: **Tauri 2 + Rust**, **Svelte 5 (runes) + TypeScript**, **vanilla CSS**.
- Платформа: **только macOS** (13+). Windows/Linux — позже, без изменения
  текущего поведения macOS.
- Bundle id: `com.button.s`. Приложение трей-онли: `LSUIElement` +
  `Accessory`; не добавлять постоянную иконку в Dock.

## 2. Источники истины

| Файл | Роль |
|---|---|
| `.internal/TZ.md` | Исходные требования (локально, не публикуется). Читать по нужному разделу, а не целиком каждый раз. |
| `.internal/context.md` | Текущее состояние: архитектура, решения, отличия от ТЗ, что сделано и что нет (локально, не публикуется). **Читать первым.** |
| `AGENTS.md` | Этот файл: правила работы. |
| `NOTICE.txt` | Лицензии сторонних словарей. |

- `.internal/context.md` может отставать от кода. Перед выводами **сверяйся с
  кодом и git**, а не только с ним.
- После значимой фичи, архитектурного решения, миграции или смены контракта —
  **обнови `.internal/context.md`** (кратко, без истории).
- Не создавай новые `.md` в корне без просьбы. Публичная документация —
  `README.md`, `UPDATES.md`, `LICENSE.md`, `SECURITY.md`, `CONTRIBUTING.md`,
  `CODE_OF_CONDUCT.md`, `NOTICE.txt` и этот файл; внутренние — в `.internal/`.
- В `.internal/context.md` и `.internal/TZ.md` не писать секреты, ключи, реальные
  данные пользователя и личные пути.

## 3. Проверка перед сдачей

```bash
npm run check                                        # svelte-check, 0 ошибок
npm run build                                        # vite build
cargo test --manifest-path src-tauri/Cargo.toml      # юнит/интеграционные тесты
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets
cargo build --manifest-path src-tauri/Cargo.toml     # debug-бинарник
```

- Минимум для любой правки: `npm run check` + релевантные `cargo test`.
- Менял бэкенд — прогоняй `cargo clippy`; проект держим на **0 warnings**.
- UI или системное поведение проверяй запуском:
  `./src-tauri/target/debug/button-s --settings`
  или собранным `.app` через `open ... --args --settings`.
- Разрешения macOS (Accessibility / Input Monitoring) в тестовой среде могут
  отсутствовать. Не считай отсутствие permissions багом кода.
- Не запускай `cargo clean` и не удаляй `src-tauri/target/`: там лежит тяжёлая
  сборка `llama-cpp-2`/`whisper-rs`, полная пересборка занимает много времени.

## 5. Конвенции изменений

### Новая IPC-команда
Три обязательных места:
1. `#[tauri::command]` в `src-tauri/src/commands.rs`;
2. регистрация в `generate_handler![]` в `src-tauri/src/lib.rs`;
3. типизированный вызов в `src/lib/api.ts`.

### Новая строка в UI
- Добавлять **сразу в оба словаря** `strings.ru` и `strings.en` в
  `src/lib/i18n.ts`; тип `Strings` не даст забыть.
- Хоткеи показывать через `prettyCombo()`.
- Ошибки бэкенда сейчас приходят готовыми русскими строками; новые
  пользовательские тексты лучше отдавать кодом/ключом, если это не ломает
  существующий контракт.

### Конфиг
- Схема сейчас **v3**. Любое изменение структуры — новая версия схемы и
  миграция; существующий `config.json` не должен ломаться.
- Повреждённый конфиг сохраняется в `.json.broken`, приложение стартует на
  дефолтах.
- Секреты (API-ключи) — только Keychain (`com.button.s`), никогда в
  `config.json`, `.env` или логи.

### UI
- Никаких CSS-фреймворков, Tailwind и UI-китов. Только классы в `app.css` и
  scoped-стили компонентов.
- Соблюдать macOS-эстетику и текущую структуру sidebar.
- Окна `hud` и `result` создаются в рантайме (`lib.rs`) с URL
  `index.html#hud` / `index.html#result`. Не дублировать их и не добавлять в
  `tauri.conf.json`.
- При добавлении окна обновить `src-tauri/capabilities/default.json`
  (`windows` + нужные permissions).

### Тексты
- Код и идентификаторы — английские; UI — русский по умолчанию + полный EN.
- Комментарии в коде не добавлять без запроса.
- Пользователю отвечать **по-русски**, кратко и по делу.

## 6. Безопасность и приватность

- Не логировать пользовательский текст, содержимое буфера и аудио.
- История по умолчанию выключена; при выключенном `privacy.historyText`
  хранить только метаданные.
- В защищённых полях (`IsSecureEventInputEnabled`) ввод не буферизуется и не
  исправляется; менеджеры паролей исключены из всех функций.
- Никакой телеметрии и скрытых сетевых запросов. Сеть — только к явно
  настроенным провайдерам и на скачивание моделей по действию пользователя.
- Не читать и не изменять личные файлы пользователя вне репозитория.
- Не коммитить модели (`.gguf`, `ggml-*.bin`), ключи, историю, дампы и
  пользовательские данные. Они лежат в
  `~/Library/Application Support/com.button.s/`.
- Разрушительные операции (`rm -rf`, `git reset --hard`, `git clean`,
  удаление Keychain/TCC, установка в `/Applications`) — только по явной
  просьбе пользователя.

## 7. macOS-специфика

- Accessibility нужен для инъекции, Input Monitoring — для перехвата,
  микрофон — только для диктовки. Все три проверяются и запрашиваются в
  `platform/macos/permissions.rs` (запросы идут последовательно).
- При смене подписи/сертификата TCC-разрешения могут сброситься — это не баг
  приложения; предупреди пользователя.
- Listen-only event tap, инъекция через CGEvent, anti-loop через
  `MAGIC_MARKER` — не менять без понимания последствий.
- Не отключать `LSUIElement`, `Accessory` и трей.
- Не трогать `ffi.rs` вслепую: там ручные объявления CoreGraphics/AX/TIS.

## 8. Дорогие и рискованные операции

- `cargo clean`, удаление `target/`, пересборка `llama-cpp-2` — долго; только
  при реальной необходимости.
- Скачивание моделей (Whisper 78 МБ–1.6 ГБ, LLM 250 МБ–2.5 ГБ) — только по
  действию пользователя; в репозиторий не добавлять.
- Не запускать несколько субагентов-писателей одновременно над одними файлами.
- Не менять схему БД без миграции; `history.db` может содержать данные
  пользователя.

## 9. Процесс работы

1. Прочитать `.internal/context.md`, этот файл и нужный раздел `.internal/TZ.md`
   (если внутренние документы есть на диске).
2. Проверить `git status`, чтобы не смешать свою работу с чужими правками.
3. Найти затронутые файлы; для крупного исследования использовать субагента.
4. Делать **минимальное полное изменение** (ponytail: без YAGNI и
   оверинжиниринга), не переписывать соседний код «заодно».
5. Добавить/обновить тесты рядом с кодом.
6. Прогнать проверки из §3.
7. Обновить `.internal/context.md`, если изменилось поведение, архитектура, схема
   или известные ограничения.
8. Закоммитить логически цельный срез.

### Субагенты
- Исследование и чтение больших объёмов — субагенту; реализацию можно делать
  самому.
- **Один субагент = один концерн.** Не давать огромные многосоставные задачи.
- Одновременно — не более одного субагента-писателя.
- Промпты субагентам и их ответы — на английском; пользователю пересказ — на
  русском.
- В промпте явно указывать: что сделать, что вернуть, можно ли менять файлы.

## 10. Git

- Долгоживущая ветка — **`main`** (фактическая; remote пока не настроен).
- Не переписывать историю, не делать force-push, не удалять чужие правки.
- Коммит — после проверенного, логически цельного среза. Сообщение осмысленное,
  на английском или русском, но единообразно.
- Не коммитить артефакты: `node_modules/`, `dist/`, `src-tauri/target/`,
  `src-tauri/gen/`, `.DS_Store`, логи и модели — они в `.gitignore`.
- Если в рабочем дереве есть незакоммиченные правки пользователя — не
  откатывать их; уточнить, включать ли в коммит.
- `push` — только если remote настроен; сейчас его нет.

## 11. Definition of Done

- Код собирается, `npm run check` и релевантные тесты зелёные.
- `cargo clippy` без новых warnings.
- Нет секретов, пользовательских данных и артефактов сборки в диффе.
- Новые строки есть в обоих языках; новые команды зарегистрированы во всех
  трёх местах.
- Схема конфига/БД совместима или мигрирована.
- `.internal/context.md` обновлён, если это требуется.
- Для UI/системного поведения — выполнена ручная проверка или явно указано,
  что она не проводилась.

## 12. Чего не делать

- Не добавлять Tailwind, React, сторонние UI-фреймворки, «на всякий случай»
  зависимости.
- Не тащить Windows/Linux-код в macOS-срез без просьбы.
- Не менять формат хоткеев, bundle id, пути данных и ключи Keychain без
  миграции.
- Не скрывать известные ограничения: если что-то не проверено — сказать прямо.
- Не устанавливать приложение в `/Applications` и не менять системные
  разрешения без явной команды.
