# Обновления BUTTON-S

## Для пользователей

Автоматических обновлений пока нет: новая версия ставится вручную поверх старой. Настройки, словари и скачанные модели при этом сохраняются.

### Как проверить новую версию

1. Откройте раздел **Releases** репозитория — на GitVerse или в зеркале на GitHub
   (файлы и контрольные суммы одинаковые):
   https://gitverse.ru/mibazarow/Button-S-local-corrector/releases
   https://github.com/mibazarow/Button-S-local-corrector/releases
2. Посмотрите последнюю версию. Если она новее установленной — скачайте DMG.
3. Перед установкой закройте BUTTON-S: иконка **S** в строке меню → **Выход**.
4. Откройте DMG и перетащите **BUTTON-S** в `Applications`, подтвердив замену.
5. Запустите приложение.

Версию можно посмотреть в настройках, внизу слева: `v1.2.0`.

### Если macOS не запускает новую сборку

Сборки пока не нотаризованы. При первом запуске может понадобиться:

- правый клик по **BUTTON-S** → **Открыть**;
- либо **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**.

### Разрешения после обновления

Если приложение подписано тем же сертификатом и bundle id не менялся, разрешения обычно сохраняются. Если macOS снова их попросит — выдайте:

- **Универсальный доступ** — для вставки исправленного текста;
- **Мониторинг ввода** — для перехвата клавиатуры;
- **Микрофон** — только для диктовки.

После выдачи разрешений перезапустите BUTTON-S.

### Важно

- Не запускайте приложение прямо из DMG — только из `Applications`.
- Не держите две копии BUTTON-S в разных папках.
- Модели Whisper и локальные LLM не входят в DMG; они скачиваются отдельно и остаются в папке данных приложения.

## Для разработчика

Текущее состояние: реализовано **уведомление о новой версии** (вариант 1 ниже) — приложение раз в 8 часов читает страницу релизов GitVerse и показывает ненарокомандный баннер со ссылкой. Автоустановка не делается. Тумблер `general.checkUpdates` отключает проверку. Приложение подписано **Apple Development** и не нотаризовано — для публичных пользователей этого недостаточно.

### Блокер: подпись и нотаризация

Для распространения на чужие Mac нужны:

- сертификат **Developer ID Application** (не Apple Development);
- hardened runtime;
- нотаризация Apple и stapling;
- проверка `spctl`.

Пример:

```bash
codesign --deep --force --options runtime \
  --sign "Developer ID Application: ..." BUTTON-S.app

xcrun notarytool submit BUTTON-S.dmg \
  --apple-id "$APPLE_ID" \
  --team-id "$APPLE_TEAM_ID" \
  --password "$APPLE_APP_PASSWORD" \
  --wait

xcrun stapler staple BUTTON-S.dmg
spctl --assess --type execute --verbose BUTTON-S.app
```

Tauri умеет подписывать и нотаризовать через переменные окружения (`APPLE_CERTIFICATE`, `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID`) — это удобно вынести в CI.

Без Developer ID и нотаризации автообновление может работать на вашем Mac, но у обычных пользователей останется проблема первого запуска и доверия Gatekeeper.

## Вариант 1. Уведомление о новой версии (реализовано)

Приложение читает страницу релизов GitVerse, сравнивает теги и показывает баннер со ссылкой на релиз; пользователь скачивает DMG сам. Реализация — `src-tauri/src/update.rs`, кэш `update-check.json` в папке данных, интервал 8 часов, три последних результата.

Пример `latest.json`:

```json
{
  "version": "1.0.1",
  "date": "2026-10-25",
  "notes": "Что нового...",
  "url": "https://gitverse.ru/mibazarow/Button-S-local-corrector/releases/tag/v1.0.1"
}
```

Логика:

1. Раз в 12–24 часа (и по кнопке «Проверить обновления») запросить JSON.
2. Сравнить `version` с текущей версией по semver.
3. Если новее — показать неблокирующий баннер: «Доступна версия 1.0.1» → «Скачать» / «Позже».
4. Не перезапускать приложение и не прерывать ввод.

Плюсы: не нужны ключи обновлений, минимум риска.  
Минусы: установка вручную.

Где хранить `latest.json`:

- raw-файл в репозитории (просто, но возможен кэш);
- ассет релиза GitVerse;
- статический хостинг / Cloudflare R2 / S3.

## Вариант 2. Полное автообновление через Tauri Updater

Tauri Updater умеет проверить версию, скачать `.app.tar.gz`, проверить подпись, заменить приложение и перезапустить его.

### 2.1. Ключ обновлений

Ключ Tauri **не связан** с подписью Apple. Это отдельная пара для проверки артефактов обновления.

```bash
npx tauri signer generate -w ~/.tauri/button-s.key
```

- публичный ключ — в `tauri.conf.json`;
- приватный ключ — только в CI/секретах и в офлайн-бэкапе;
- если потерять приватный ключ, уже установленные приложения не смогут обновляться;
- в репозиторий приватный ключ не коммитить.

### 2.2. Конфиг

```json
{
  "bundle": {
    "createUpdaterArtifacts": true
  },
  "plugins": {
    "updater": {
      "endpoints": ["https://example.com/button-s/latest.json"],
      "pubkey": "ПУБЛИЧНЫЙ_КЛЮЧ"
    }
  }
}
```

### 2.3. Сборка

```bash
TAURI_SIGNING_PRIVATE_KEY="$HOME/.tauri/button-s.key" \
TAURI_SIGNING_PRIVATE_KEY_PASSWORD="..." \
npx tauri build
```

На выходе нужны:

- `BUTTON-S_1.0.1_aarch64.dmg` — для первой установки;
- `BUTTON-S_1.0.1_aarch64.app.tar.gz` — для автообновления;
- `.sig` — подпись артефакта.

### 2.4. `latest.json`

```json
{
  "version": "1.0.1",
  "notes": "Что нового...",
  "pub_date": "2026-10-25T12:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "СОДЕРЖИМОЕ_ФАЙЛА_SIG",
      "url": "https://example.com/button-s/BUTTON-S_1.0.1_aarch64.app.tar.gz"
    }
  }
}
```

Для Intel позже добавить `darwin-x86_64`; для Windows/Linux — свои ключи платформ.

### 2.5. Проверка в приложении

Rust (Tauri v2):

```rust
use tauri_plugin_updater::UpdaterExt;

let update = app.updater()?.check().await?;
if let Some(update) = update {
    // показать пользователю версию и notes,
    // после согласия: update.download_and_install(...).await?;
}
```

UX:

- проверка при запуске с задержкой и раз в 12–24 часа;
- пункт «Проверить обновления» в трее/настройках;
- баннер «Доступна версия X» → «Обновить» / «Позже»;
- не перезапускать приложение, пока пользователь печатает;
- прогресс скачивания и понятная ошибка;
- тумблер «Проверять обновления автоматически» (поле `checkUpdates` уже есть);
- канал `stable` / `beta` через `updateChannel`.

### 2.6. Хостинг

- ассеты релиза GitVerse;
- raw `latest.json` в репозитории — самый простой стабильный URL, но учитывайте кэш;
- Cloudflare R2 / S3 / статический хостинг — надёжнее.

Для Rust-запроса CORS не важен, но файл должен открываться без авторизации.
