## 1. Общие сведения

### 1.1. Назначение документа

Настоящее техническое задание описывает требования к приложению **BUTTON-S** —
фоновому кроссплатформенному агенту для macOS, Windows и Linux, который ускоряет и
исправляет ввод текста в любых программах системы.

Документ является единственным источником истины по функциональности, архитектуре,
ограничениям и критериям приёмки. Все спорные трактовки решаются в пользу разделов
«Функциональные требования» и «Критерии приёмки».

### 1.2. Название и бренд

**BUTTON-S** — окончательное название продукта.

Смысл: игра слов «кнопка» / «кнопки» + «кнопка супер» (Super Button). Идея продукта —
одна кнопка (хоткей) ускоряет, исправляет и дополняет ввод.

Правила использования:
- в интерфейсе и текстах — строго `BUTTON-S` (латиница, заглавные, дефис);
- в коде, путях и репозитории — `button-s`, `buttons`;
- идентификаторы приложения — `ru.buttons.app` (домен уточняется);
- слоган: «Одна кнопка — весь ввод под контролем»;
- логотип, иконка и звуковые темы разрабатываются отдельно.

### 1.3. Цели продукта

1. Сократить время ввода текста в 2–5 раз за счёт автоподмены раскладки, исправления
   опечаток, голосового ввода и автозамен.
2. Дать полноценный голосовой ввод, работающий локально, без интернета и без отправки
   аудио на сторонние серверы.
3. Дать пользователю управляемый доступ к нейросетям: свои ключи, локальные модели,
   собственные промпты и горячие клавиши.
4. Обеспечить одинаковый пользовательский опыт на macOS, Windows и Linux.
5. Не стоить пользователю ничего: без подписки, аккаунта, лимитов устройств и пробных
   периодов.
6. Не собирать данные по умолчанию.

### 1.4. Принципы

- **Локальность по умолчанию.** Базовые функции работают офлайн. Любой сетевой запрос —
  только после явной настройки пользователем.
- **Не мешать.** Приложение не должно портить текст, перехватывать управление или
  замедлять ввод. Любое автоматическое действие отменяемо.
- **Прозрачность.** Пользователь видит, что и почему было исправлено, и может это
  отключить.
- **Обратимость.** Каждое автоматическое изменение имеет откат.
- **Отсутствие привязки.** Нет аккаунта, нет серверной части, обязательной для работы.
- **Расширяемость.** Языки, раскладки, модели, правила и провайдеры добавляются без
  пересборки ядра.

### 1.5. Целевая аудитория

| Сегмент | Потребность |
|---|---|
| Пользователи, печатающие на двух языках | мгновенное исправление раскладки |
| Авторы текстов, редакторы, копирайтеры | скорость набора, пунктуация, LLM-правка |
| Разработчики и аналитики | быстрый ввод в IDE/терминале, исключения для приложений |
| Люди с ограниченной моторикой | голосовой ввод без облака |
| Сотрудники с требованиями к приватности | локальная обработка, отсутствие телеметрии |
| Организации | централизованная настройка, self-hosted модели |

### 1.6. Основные сценарии использования

1. Пользователь печатает `ghbdtn` в мессенджере — получает `привет` и переключение
   раскладки.
2. Пользователь печатает `превет` — приложение исправляет на `привет`.
3. Пользователь удерживает хоткей, диктует фразу — текст с пунктуацией появляется в
   активном поле.
4. Пользователь выделяет абзац, нажимает хоткей — LLM сокращает или исправляет текст
   прямо на месте.
5. Пользователь выделяет текст и переводит его на английский одним хоткеем.
6. Пользователь добавляет редкое слово в словарь, чтобы автоподмена его не трогала.
7. Пользователь отключает все функции в терминале и IDE, оставив только голосовой ввод.
8. Пользователь набирает `->` и получает `→`.
9. Пользователь нажимает Enter в нумерованном списке — получает следующий номер.
10. Пользователь случайно набрал `ППривет` — приложение исправляет регистр.
11. Пользователь меняет регистр выделенного текста хоткеем.
12. Пользователь работает офлайн — все базовые функции продолжают работать.

### 1.7. Границы проекта

**Входит в объём:**
- фоновый агент с системным треем/меню-баром;
- перехват и анализ клавиатурного ввода;
- чтение контекста и выделения, вставка и замена текста;
- автоподмена раскладки, опечатки, словари;
- локальный голосовой ввод;
- LLM-промпты и перевод;
- автозамены, капитализация, списки, регистр, залипший Shift;
- исключения приложений, хоткеи, настройки, история;
- установщики и автообновление;
- локализация RU/EN.

**Не входит в объём первой версии:**
- мобильные приложения;
- облачный аккаунт и обязательная синхронизация;
- распознавание речи на сервере;
- поддержка игр с античитами и защищённых рабочих столов;
- автоматический перевод всего интерфейса, кроме RU/EN;
- юридически значимая расшифровка аудио;
- замена системной раскладки на уровне драйвера.

## 4. Функциональные требования

Приоритеты: **P0** — обязательное для MVP, **P1** — первый публичный релиз,
**P2** — последующее развитие. Каждый пункт считается выполненным только при наличии
автоматического или ручного теста из раздела 14.

### 4.1. Автоподмена раскладки клавиатуры

#### 4.1.1. Основное поведение

- FR-1.1. Приложение отслеживает ввод во всех приложениях ОС, где это разрешено
  системой.
- FR-1.2. По границе слова (пробел, Enter, Tab, знак препинания) анализируется
  последнее слово.
- FR-1.3. Кандидаты на замену:
  1. исходное слово;
  2. конверсия в каждую альтернативную раскладку из настроенных пар;
  3. вариант после исправления опечаток (см. 4.2).
- FR-1.4. Каждый кандидат получает оценку; при превышении порога уверенности слово
  заменяется, а раскладка ОС переключается на язык победителя.
- FR-1.5. Замена выполняется атомарно: слово + разделитель, курсор остаётся после
  разделителя.
- FR-1.6. Регистр сохраняется: `Ghbdtn` → `Привет`, `GHBDTN` → `ПРИВЕТ`.
- FR-1.7. Работает для пар RU↔EN из коробки. Пары языков и карты раскладок
  подключаются файлами (см. 8.4).
- FR-1.8. Переключение системной раскладки выполняется нативным API ОС; при
  невозможности — только замена текста с уведомлением.

#### 4.1.2. Алгоритм и скоринг

Пайплайн:

```
key events → word buffer → tokenizer → candidates
           → frequency score → n-gram score → heuristics
           → decision → inject → layout switch → undo entry
```

Правила скоринга (значения настраиваются):

1. `score = log10(freq(word)) + α·ngram(word) + β·contextBonus − γ·penalty`.
2. Частотные словари: минимум 100 000 словоформ на язык, сжатое FST-хранилище.
3. n-gram модель символов (3–5) для слов, отсутствующих в словаре.
4. Бонус, если слово уже встречалось в сессии или пользовательском словаре.
5. Штрафы: наличие цифр, смешение алфавитов, длина < `minWordLength` (по умолчанию 3),
   CapsLock, слово в защищённом списке.

Эвристики отказа от замены:
- слово есть в пользовательском словаре — не трогать;
- оба варианта валидны и исходный частотнее — не трогать;
- слово содержит `@`, `://`, `/`, `\`, `_`, `#`, `.` внутри, цифры — не трогать
  (настраиваемо);
- активно IME-состояние (CJK) — не вмешиваться;
- приложение в списке исключений — не вмешиваться.

#### 4.1.3. Ручные операции

- FR-1.9. Хоткей «конвертировать последнее слово» — принудительная замена без порога.
- FR-1.10. Хоткей «конвертировать выделение» — замена выделенного фрагмента.
- FR-1.11. Хоткей «отменить последнюю автоподмену» — возврат исходного текста и
  раскладки.
- FR-1.12. Повторный вызов конверсии выделения циклически перебирает раскладки.

#### 4.1.4. Настройки

- включение/выключение;
- список пар языков;
- порог уверенности (0.5–0.99);
- минимальная длина слова;
- автопереключение раскладки ОС (да/нет);
- задержка перед заменой (0–500 мс);
- исключения (приложения, слова, регулярные выражения);
- «показывать уведомление о подмене» (по умолчанию выключено).

#### 4.1.5. Крайние случаи

- слова с дефисом и апострофом;
- смешанные слова (`iPhone`, `Wi-Fi`);
- заглавные аббревиатуры (`ГОСТ`, `API`);
- ввод в полях с автодополнением;
- ввод в терминале (по умолчанию автоподмена выключена для известных терминалов);
- быстрый ввод с опережением (буфер не должен отставать);
- Backspace после автоподмены не должен возвращать ошибочный вариант.

#### 4.1.6. Критерии приёмки

- ≥ 95% корректных замен на наборе из 500 слов;
- ≤ 0.5% ложных замен на контрольном корпусе обычного текста;
- задержка от границы слова до замены ≤ 100 мс (p95);
- отмена возвращает текст символ в символ.

### 4.2. Исправление опечаток и орфографии

- FR-2.1. Обнаружение опечаток: пропуск, вставка, замена, перестановка соседних
  символов, двойной символ, неверный регистр.
- FR-2.2. Алгоритм: SymSpell/Damerau-Levenshtein с весом соседства клавиш, порог
  расстояния 1–2 в зависимости от длины слова.
- FR-2.3. Автоматическое исправление только при высокой уверенности; иначе — пассивное
  уведомление или ничего (режим настраивается).
- FR-2.4. Режимы: `auto` (исправлять), `suggest` (HUD с предложением и хоткеем
  применения), `off`.
- FR-2.5. Не исправлять: пользовательский словарь, аббревиатуры из словаря, слова из
  одних заглавных, URL, e-mail, пути, код, хештеги, упоминания.
- FR-2.6. Исправление выделенного фрагмента по хоткею.
- FR-2.7. Работает совместно с автоподменой: сначала проверяется конверсия раскладки,
  затем опечатка в выигравшем языке.
- FR-2.8. Изучение: если пользователь отменил исправление 2 раза для пары
  «ошибочное → предложенное», пара попадает в стоп-лист.
- FR-2.9. Русский и английский языки; расширяемо.

Критерии: precision ≥ 98% на тестовом наборе, recall ≥ 85%; ноль исправлений в
защищённых полях.

- FR-3.9. Удаление и редактирование не должны ломать активные правила; изменения
  применяются без перезапуска.
- FR-3.10. Поиск и фильтрация по языку/тегу.

### 4.4. Голосовой ввод

#### 4.4.1. Запуск и режимы

- FR-4.1. Режим push-to-talk: запись, пока удерживается хоткей.
- FR-4.2. Режим toggle: первое нажатие — старт, второе — стоп.
- FR-4.3. Режим VAD: старт по хоткею, автоматическая остановка после тишины.
- FR-4.4. Отмена записи без вставки (Esc или повторный хоткей в режиме отмены).
- FR-4.5. HUD показывает: запись, уровень сигнала, распознавание, ошибку; HUD не
  забирает фокус и не перекрывает поле ввода.

#### 4.4.2. Аудио

- FR-4.6. Захват: 16 кГц, моно, PCM 16 бит; внутренняя обработка допускает 48 кГц с
  ресемплингом.
- FR-4.7. Выбор устройства ввода; запоминание последнего рабочего.
- FR-4.8. Нормализация громкости; опциональное шумоподавление.
- FR-4.9. VAD: Silero; порог, минимальная длина речи (200 мс), пауза завершения
  (1.5 с), паддинги 200 мс.
- FR-4.10. Максимальная длительность записи по умолчанию 5 минут (настраивается).
- FR-4.11. Аудио хранится только в RAM; запись на диск — опция, выключена по умолчанию.

#### 4.4.3. Распознавание

- FR-4.12. Движки: `sherpa-onnx` (по умолчанию) и `whisper.cpp`; выбор в настройках.
- FR-4.13. Языки: русский, английский; автоопределение языка (P1).
- FR-4.14. Менеджер моделей: каталог, размер, лицензия, скачивание с проверкой
  контрольной суммы, докачка, удаление, обновление.
- FR-4.15. Встроенная компактная модель для установки офлайн.
- FR-4.16. Постобработка:
  - расстановка пунктуации и капитализация;
  - удаление слов-паразитов (опция);
  - применение пользовательских замен и словаря;
  - сохранение исходного варианта для отмены.
- FR-4.17. Частичные результаты (стриминг) — P2.
- FR-4.18. Распознавание шёпота и тихой речи — целевое требование к качеству, а не
  отдельный режим.

#### 4.4.4. Вставка результата

- FR-4.19. По умолчанию — «печать» символов в активное поле; при недоступности —
  вставка через буфер обмена с восстановлением содержимого буфера.
- FR-4.20. Если активное поле недоступно: результат копируется в буфер и показывается
  уведомление.
- FR-4.21. В защищённых полях голосовой ввод отключён, текст не буферизуется.
- FR-4.22. Вставка не должна ломать позицию курсора и выделение за пределами точки
  вставки.
- FR-4.23. Вставка длинного текста — чанками с возможностью отмены.

#### 4.4.5. Ошибки

- нет разрешения на микрофон;
- устройство занято/отключено;
- модель не найдена или повреждена;
- нет речи / слишком короткая запись;
- переполнение буфера;
- вставка запрещена приложением.

Для каждой — понятное сообщение и действие восстановления.

#### 4.4.6. Критерии приёмки

- WER ≤ 7% на подготовленном наборе чистой русской речи, ≤ 12% на шумной.
- Задержка от конца речи до вставки ≤ 1.5 с для фразы до 10 секунд (p95).
- Работа без сети на всех поддерживаемых ОС.
- Пунктуация расставлена в ≥ 90% тестовых фраз.

## 5. Нефункциональные требования

### 5.1. Производительность

| Метрика | Требование |
|---|---|
| Задержка обработки нажатия | ≤ 2 мс (p99), хук не блокирует ввод |
| Задержка автоподмены | ≤ 100 мс после границы слова (p95) |
| Задержка голосового ввода | ≤ 1.5 с после конца речи (p95) |
| Потребление RAM в покое | ≤ 150 МБ без ASR-модели |
| Потребление RAM с ASR | ≤ 800 МБ (модель ≤ 500 МБ) |
| CPU в покое | ≤ 1% на 4-ядерном CPU |
| CPU при диктовке | ≤ 60% одного ядра |
| Старт приложения | ≤ 2 с до готовности |
| Размер установщика | ≤ 60 МБ без моделей |
| Размер моделей | компактная ASR ≤ 150 МБ, качественная ≤ 500 МБ |

### 5.2. Надёжность

- Crash-free sessions ≥ 99.5%.
- Отсутствие потери текста при сбое: операция либо завершена, либо отменена.
- Восстановление после сна/пробуждения, смены устройства аудио, отключения микрофона.
- Работа 8 часов в фоне без утечек памяти (рост RSS ≤ 10%).
- Корректная работа при нескольких мониторах и смене активного приложения.

### 5.3. Совместимость

Проверяется в: Safari, Chrome, Firefox, Edge, Slack, Telegram, Discord, Notion,
Obsidian, VS Code, JetBrains IDE, Microsoft Office, Google Docs, Apple Pages, Word,
LibreOffice, iTerm2, Terminal, Windows Terminal, Finder/Explorer, почтовых клиентах.

### 5.4. UX

- Любое автоматическое действие можно отменить.
- Все состояния (запись, обработка, ошибка) видимы.
- Настройки применяются без перезапуска, где это возможно.
- Время до первого полезного результата после установки ≤ 3 минуты.
- Подсказки о разрешениях содержат точный путь в системе.

### 5.5. Доступность

- Полное управление с клавиатуры.
- Совместимость с VoiceOver/NVDA/Orca для окна настроек.
- Контраст ≥ WCAG AA, масштабирование интерфейса.
- Отсутствие мигания, уважение `prefers-reduced-motion`.

### 5.6. Локализация

- RU, EN в первой версии; строки в JSON/YAML.
- Форматы дат/чисел по локали.
- Раскладки и словари независимы от языка интерфейса.

### 5.7. Ограничения и допущения

- Для работы хуков требуются разрешения ОС; без них функциональность ограничена.
- Wayland не позволяет глобальный перехват без модуля композитора/IBus.
- Античит-игры и защищённые рабочие столы не поддерживаются.
- Качество ASR зависит от модели, микрофона и шума.

### 6.2. Потоки и конкурентность

- Поток хука клавиатуры: только сбор событий и минимум логики, без аллокаций в горячем
  пути; отправка в канал.
- Поток анализа текста: debounce, скоринг, решение.
- Поток инжекта: сериализованная очередь операций; одна операция за раз.
- Аудиопоток: lock-free кольцевой буфер.
- ASR/LLM: пул рабочих потоков, отмена по токену.
- Сеть: асинхронный рантайм (tokio) в отдельном контуре.
- UI ↔ Core: IPC Tauri-команд и событий; состояние в `Arc<RwLock<...>>`.

### 6.3. Платформенные абстракции


Аналогично: `PlatformAudio`, `PlatformSecrets`, `PlatformAutostart`, `PlatformUpdater`.
Реализации: `platform/macos.rs`, `platform/windows.rs`, `platform/linux.rs`. Windows и
Linux компилируются с первого дня (заглушки), чтобы CI не расходился.

### 6.4. Стек (утверждён)

- Ядро: Rust 2021+, `serde`, `tokio`, `rusqlite`, `parking_lot`, `tracing`.
- UI: Tauri 2 + TypeScript + Svelte (React допустим).
- Ввод: `global-hotkey`, `rdev` (с собственными fallback-реализациями), `enigo`,
  `arboard`.
- Аудио: `cpal`.
- ASR: `sherpa-onnx` (основной), `whisper-rs` (альтернатива).

### 6.5. Стратегия портирования

1. Этап A — macOS: полный продукт и стабильный `PlatformInput`.
2. Этап B — Windows: реализация трейта (хук, UIA, SendInput), остальное переиспользуется.
3. Этап C — Linux: X11 полностью, Wayland — IBus/Fcitx-модуль или evdev+uinput.

Вся бизнес-логика пишется один раз и не содержит `cfg(target_os)` вне platform-слоя.

## 8. Особенности платформ

### 8.1. macOS

- Разрешения: Accessibility (обязательно), Input Monitoring, Microphone, Automation
  (если нужно управление чужими приложениями).
- Чтение контекста: Accessibility API; для приложений без поддержки — ограниченный
  режим (только выделение через буфер).
- Перехват: `CGEventTap` (listen + annotate) в отдельном run loop.
- Вставка: `CGEvent` с Unicode-строками, fallback — `NSPasteboard` + Cmd+V.
- Secure input: `IsSecureEventInputEnabled()` → полное отключение функций и очистка
  буферов.
- Переключение раскладки: TIS (Text Input Sources API).
- Автозапуск: LaunchAgent; в песочнице не работает — sandbox отключён.
- Подпись Developer ID, notarization, hardened runtime с исключением для хука.
- Обновления: Sparkle-совместимый/собственный updater с EdDSA-подписью.

### 8.2. Windows

- Перехват: `SetWindowsHookEx(WH_KEYBOARD_LL)` в выделенном потоке с минимальной
  обработкой.
- Чтение контекста: UI Automation; fallback — буфер обмена.
- Вставка: `SendInput` с `KEYEVENTF_UNICODE`; для rich-полей — буфер + Ctrl+V.
- Определение приложения: exe, publisher, window class.
- Secure desktop/UAC/LogonUI — функции отключены.
- Повышенные приложения: приложение не работает из-под обычных прав в окнах,
  запущенных от администратора; показывается предупреждение.
- Автозапуск: ключ Run или Планировщик задач (настраиваемо).
- Подпись EV/OV сертификатом; минимизация ложных срабатываний антивирусов.

### 8.3. Linux

- X11: XRecord для чтения, XTEST для вставки, XKB для раскладок — полная поддержка.
- Wayland:
  - прямой глобальный хук невозможен;
  - вариант 1: модуль IBus/Fcitx5 (полноценная интеграция в поддерживаемых
    приложениях);
  - вариант 2: evdev + uinput (требует прав группы `input`/udev-правила);
  - ограничения явно отображаются в UI.
- Вставка: `ydotool`-подобный механизм через uinput либо буфер + Ctrl+V.
- Аудио: PipeWire/PulseAudio через `cpal`.
- Пакеты: `.deb`, `.rpm`, AppImage; Flatpak с оговоркой об ограничениях порталов.
- Автозапуск: `.desktop` в `~/.config/autostart`.

## 14. Риски и меры

| Риск | Влияние | Мера |
|---|---|---|
| Ложные автоподмены портят текст | отток пользователей | порог, отмена, обучение на отменах, стоп-лист |
| Wayland не даёт глобальный хук | ограничение Linux | IBus/Fcitx-модуль, evdev+uinput, честный UI |
| Антивирусы блокируют хуки/инжект | невозможность установки | подпись, открытый код, документация, отказ от обфускации |
| Размер ASR-моделей | тяжёлый дистрибутив | модели по требованию, компактный дефолт |
| Разрешения macOS не выданы | не работает | онбординг, диагностика, понятные ошибки |
| Лицензии моделей | юридические риски | аудит лицензий, permissive-модели |
| Гонки при инжекте | потеря текста | очередь операций, идемпотентность, откат |
| Падение производительности на слабых CPU | плохой UX | квантизация, ограничение модели, профилирование |
| Конфликты хоткеев | неудобство | обнаружение, рекомендации, сброс |
