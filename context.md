# CONTEXT.md — BUTTON-S: состояние проекта для быстрого въезда

Обновлено: 2026-10-24, после четырёх сессий (редизайн+провайдеры → каталог
Whisper → встроенные локальные LLM → релиз 1.0.0). Читать этот файл первым;
исходные требования — TZ.md.

---

## 1. Проект в двух словах

**BUTTON-S** — фоновый ускоритель ввода для macOS (меню-бар): автоподмена
раскладки (`ghbdtn → привет`), опечатки, автозамены символов, капитализация,
списки, залипший Shift, голосовой ввод (Whisper, локально), LLM-промпты и
перевод, словари, исключения приложений. Версия 1.0.0, только macOS.
Bundle id — `com.button.s` (переименован с `ru.buttons.app`); данные, модели,
Keychain и TCC старого id вычищены. История, резервные копии и диагностика
убраны из интерфейса.

Стек: **Rust + Tauri 2** (`src-tauri/`), **Svelte 5 (runes) + TypeScript**
(`src/`). Исходные требования — TZ.md, но реализация местами ушла вперёд —
отличия ниже.

## 2. Как собирать и проверять

```bash
npm run check        # svelte-check — 0 ошибок
npm run build        # vite build — чисто
cargo test --manifest-path src-tauri/Cargo.toml   # 35 тестов, все зелёные
cargo build --manifest-path src-tauri/Cargo.toml  # debug-бинарь ~58 МБ
./src-tauri/target/debug/button-s --settings      # запуск с окном настроек
npx tauri build                                   # release .app + .dmg
```

llama.cpp (крейт llama-cpp-2, vendored + cmake) уже скомпилирован в target/ —
пересборка инкрементальная. Конфиг юзера:
`~/Library/Application Support/com.button.s/config.json`, модели — рядом в
`models/` (whisper) и `models/llm/` (GGUF). Рабочее дерево чистое, релиз 1.0.0
закоммичен и установлен в `/Applications/BUTTON-S.app`; DMG —
`src-tauri/target/release/bundle/dmg/BUTTON-S_1.0.0_aarch64.dmg`.

## 3. Ключевые решения (главное, что нужно знать)

### 3.1. LM-провайдеры — без заготовок (переопределяет TZ §FR-5.4)

Никаких preset'ов. Пользователь добавляет провайдеров сам: форма в AiTab
(название, endpoint, токен) → кнопка «Подключить» вызывает `provider_discover`,
который **автодетектит протокол** (Ollama `/api/tags` → OpenAI `/models`,
`/v1/models` → Anthropic `/v1/models` c `x-api-key`; Anthropic-хост проверяется
первым) и **тянет список моделей с endpoint** — юзер выбирает из списка (или
вручную, если API не отдаёт). Провайдеров сколько угодно, **активен ровно один**
(`llm.defaultProvider`), переключение кликом по строке. Ключи — keychain
(service `com.button.s`, account = `keyRef` вида `provider:{name}`);
повторное «Подключить» берёт ключ из keychain. Список моделей кэшируется в
`Provider.models` → выпадающий список в редакторе промптов.

- Схема конфига **v3**; миграция v2→v3 (`migrate_v2_to_v3`) сносит нетронутые
  пресеты старой версии и сразу перезаписывает файл.
- Команды: `save_provider` (с `original` для rename — перенос ключа и default),
  `provider_discover(base_url, key, key_ref)`, `delete_provider` (стирает и
  ключ), `set_default_provider`.
- URL нормализуется (`normalize_base_url`: http для localhost, https остальным).

### 3.2. Встроенные локальные LLM (llama.cpp) — фишка против KeyRay

Полностью офлайн-режим без облака и без установки Ollama. Рантайм — крейт
**llama-cpp-2** (vendored llama.cpp, cmake, Metal через
`with_n_gpu_layers(u32::MAX)`).

- **Каталог 6 моделей** (GGUF Q4_K_M) в `llm_local.rs`: Gemma 3 270M (~253 МБ,
  unsloth — «лёгкая, попробовать»), **Vikhr-Qwen 0.5B** (~398 МБ),
  **Vikhr-Llama 1B** (~808 МБ) и **Vikhr-Gemma 2B** (~1.7 ГБ) —
  русскоязычные от Vikhrmodels (официальные GGUF; линейка «0.5B похуже →
  1B получше → 2B уверенная», с пометкой «заточены под русский»), Qwen3 1.7B
  (~1.1 ГБ, unsloth — универсальная рекомендуемая), Qwen3 4B (~2.5 ГБ,
  официал. Qwen — «без компромиссов»). «Большие русские» (T-lite / Saiga ~5 ГБ)
  и YandexGPT-5-Lite-8B не добавлены: у YandexGPT нет instruct-GGUF (только
  pretrain от сообщества, непригоден). Качаются в `models/llm/` с прогрессом
  (событие `llm-model-download`). Каталог строго отсортирован по размеру —
  это проверяет тест `catalog_is_sorted_by_size`.
- Провайдер **`local`** (kind="local", base_url="local://") — создаётся
  автоматически при скачивании/«Использовать». В UI — **первый пункт общего
  списка провайдеров** (не отдельная секция): бейдж «Встроенная · офлайн»,
  подпись «скачается и будет запускаться локально вместе с приложением»,
  кнопка «Модели» раскрывает панель (пояснение «для чего ИИ» + дисклеймер о
  качестве + каталог). После скачивания переключается с облаками как обычный.
- Рантайм: модель грузится **лениво при первом запросе**, выгружается через
  **90 с простоя** (чистильщик-поток) — память не жрёт в покое. N_CTX 4096,
  ≤1024 токенов, chat-шаблон из модели + системное сообщение.
- **Размышления отключены везде** (юзер: «текстовые задачи, не код»): Qwen3 —
  мягкий переключатель `/no_think` в системном промпте + страховка
  `strip_thinking` (`<think>`-блоки вырезаются; незакрытый блок = ошибка),
  Ollama — `"think": false`, OpenAI reasoning-модели (o1/o3/o4/gpt-5*) —
  `reasoning_effort` low/minimal (эвристика `reasoning_effort_for` по имени
  модели; обычным gpt-4o и др. параметр не шлётся — иначе 400). Общий
  системный промпт — `llm.rs::SYSTEM_PROMPT` (одна строка, ~20 токенов,
  минимальный префил), шлётся **всем** веткам: openai (system message),
  anthropic (top-level system), ollama (system), local.
- Встроенные промпты (`llm.rs::builtin_prompts`, 7 шт.): исправить
  орфографию (⌘⌥F по умолчанию), сократить, переписать официально,
  **перефразировать** и **улучшить** (добавлены 2026-10-24), суммировать,
  ответить на письмо; + перевод RU↔EN хоткеями. Срабатывание: выделение →
  хоткей/«Запустить» → активный провайдер → вывод (replace/popup/copy/append).
- **Свой комментарий к любой заготовке** (2026-10-24, юзер: «приписать свой
  комментарий, ненавязчиво»): поле `Prompt.note` — необязательная добавка,
  приклеивается к заполненному шаблону как «Дополнительное указание от
  пользователя: …» (`llm::with_note`, применяется в `run_prompt`). В редакторе
  промптов — поле «Свой комментарий» с примерами-подсказками. Работает и для
  встроенных, и для своих промптов; старый prompts.json совместим (serde
  default). Свои промпты — с переменными
  {{text}}/{{clipboard}}/{{language}}/{{app}}/{{date}}.
- Команды: `llm_local_models`, `llm_local_download(id)`, `llm_local_use(id)`.
- Директория рантайма — `llm_local::set_dir()` в setup (OnceLock); UI-команды
  берут пути от `state.config_path` (тестируемо).

### 3.3. Каталог Whisper-моделей (голос)

5 моделей на выбор вместо одной: **tiny** 78 МБ → **base** 148 МБ → **small**
488 МБ → **medium** 1.5 ГБ → **large-v3-turbo** 1.6 ГБ (все multilingual RU+EN,
HuggingFace ggerganov/whisper.cpp, в `models/`). Скачивание с прогрессом,
переключение «Использовать», «Активная» = скачана И указана в
`config.voice.model`. VoiceTab — карточки с описаниями-градацией. Команды:
`voice_models`, `voice_use_model`, `voice_download_model(id)`.

**У каждой модели (и Whisper, и локальных LLM) в карточке — сильные и слабые
стороны**: две строки с зелёной (плюс: скорость/ресурсы/точность) и янтарной
(честный минус: ошибки/вес/нагрузка) точками. Ключи i18n — `model<X>Pro/Con` и
`localLlm<X>Pro/Con`, разметка — список `.traits` в VoiceTab/AiTab.

### 3.4. UI-архитектура

- **Sidebar-навигация** (7 секций: Основное, Голос, Словарь, Замены,
  Приложения, ИИ, Хоткеи), иконки+подписи; окно 880×640 (min 720×540).
  История, резервные копии, диагностика и раздел «Данные» удалены из UI;
  history принудительно выключена в `Config::normalize`.
- **i18n** — `src/lib/i18n.ts`: типизированный словарь `strings.ru/en` (en:
  Strings гарантирует полноту), `prettyCombo()` («Command+Alt+KeyZ» → «⌘ ⌥ Z»).
- Иконки — `src/lib/Icon.svelte` (inline SVG, stroke).
- **Callout** (`src/lib/Callout.svelte`) — единая аккуратная рамка-инструкция
  сверху разделов «Голос», «Словарь», «Замены», «Приложения», «ИИ».
- **AppsTab** — список пуст по умолчанию. «Обзор» открывает нативный выбор
  `.app`, бэкенд читает `Contents/Info.plist` (bundle id + имя) и добавляет
  запись. В списке только один тумблер «включено/выключено» и удаление из
  списка; исключённые по умолчанию (терминалы, менеджеры паролей) показаны
  только для информации и не редактируются.
- **AiTab** — сначала объяснение, зачем нужен ИИ; отдельный блок облачных
  провайдеров и отдельный блок локальных моделей с пояснениями и каталогом.
  Промпты переименованы в «Действия с текстом», получили инструкцию, а
  технические поля (провайдер/модель/температура/переменные) спрятаны в
  «Дополнительные настройки».
- **Разрешения запрашиваются сразу все**: Accessibility → Input Monitoring →
  Microphone, последовательно с паузами; в главном экране есть три строки
  статуса и кнопки открытия системных настроек. Микрофон нужен только для
  диктовки и не блокирует автоподмену.
- **Удаление моделей** — у скачанных Whisper и локальных LLM есть мягкая
  красная кнопка «Удалить» рядом с «Использовать/Готово»; у облачных
  провайдеров кнопка удаления тоже текстовая. Удаление активной модели
  переключает на другую скачанную (Whisper) или сбрасывает провайдер (LLM).
- **Хоткей диктовки выбирается прямо в VoiceTab**: кнопка «Изменить» ловит
  сочетание и вызывает `set_hotkey("dictate")`; источник истины —
  `config.hotkeys.dictate`, поле `voice.hotkey` синхронизируется для старых
  конфигов.
- **tauri-plugin-dialog** — нативные диалоги для импорта/экспорта словарей и
  выбора приложения в AppsTab.

## 6. Исправленные баги (чтобы не/regрессить)

1. Хоткеи промптов не перерегистрировались после save/delete_prompt.
2. Rename провайдера оставлял дубль в конфиге (ключ терялся).
3. Новый промпт не оставался выбранным после сохранения (id генерится на бэке).
4. Ошибка «нет связи» не матчилась по регистру → невнятный текст юзеру.
5. Нескачанная Whisper-base помечалась «Активная» (UI показывал «Готово»).
6. Незакрытый `<think>` Qwen3 выдавал «размышления» вместо ошибки.
7. `TISCopyInputSourceForLanguage` вызывался из фонового потока движка →
   `dispatch_assert_queue_fail`/SIGTRAP при первой автоподмене раскладки.
   Переключение раскладки теперь уходит в main thread через
   `AppState::switch_layout`.
8. «Раскладка не работает» после релиза: приложение было штатно закрыто
   через «Выход» в трее (exit 0). Функции работают только пока процесс жив;
   закрытие окна настроек процесс не завершает.

## 7. Ограничения и что сделать дальше

- **UI не проверен глазами** — у среды нет Screen Recording; визуальная
  приёмка за пользователем (особенно новые Callout, AppsTab и AiTab).
- **Реальная генерация локальной LLM не проверена** — нужно скачать хотя бы
  Gemma и запустить промпт из приложения.
- История, резервные копии и диагностика убраны из UI; backend-команды и
  `history.db` пока оставлены, но история принудительно выключена. Если
  понадобится «вычистить» совсем — удалить модуль/команды отдельным срезом.
- Выбор `.app` в AppsTab проверен только чтением Info.plist в тесте; нативный
  диалог и поведение macOS-пакетов нужно проверить руками.
- **Релиз 1.0.0 собран и установлен** в `/Applications/BUTTON-S.app` (Apple
  Development, hardened runtime, без нотаризации). В `[profile.release]` явно
  стоит `strip = false`: на Xcode 27 + текущем rustc дефолтный
  `strip=debuginfo` даёт proc-macro dylib с `mis-aligned LINKEDIT string pool`,
  и dyld не может их загрузить (`can't find crate for *_derive`). С
  `strip = false` default `npx tauri build` работает без env-хака. Бинарник
  ~16 МБ.
- После переустановки/переподписи TCC-разрешения могут потребовать повторной
  выдачи — это ожидаемо.
- Перевод идёт только через активного провайдера; локальный Opus-MT/NLLB не
  реализован (идея из TZ §FR-6.2).
- Стриминг LLM в попап (FR-5.8) не реализован; отмена длинного запроса — нет.
- Запись хоткея промпта — текстовое поле (не capture клавиш).
